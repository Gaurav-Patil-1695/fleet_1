# fleet_1

Generated by the Implementation service from a Design Package.

> React (vite) | Fastapi | Postgres | JWT auth | Docker

## Features
- **Service Scheduling**: Requirements grouped under the "Service Scheduling" capability
- **Work Orders**: Requirements grouped under the "Work Orders" capability
- **Telematics Odometer Ingestion**: Requirements grouped under the "Telematics Odometer Ingestion" capability
- **Vehicle Register**: Requirements grouped under the "Vehicle Register" capability

### User roles
- **Administrator**: Privileged user who configures the platform and manages users, roles, content, and settings.
- **Manager**: Oversees a functional area and approves or supervises the work within it.
- **Technician**: Carries out assigned maintenance or service work and records its completion.

## Getting started

### Prerequisites

- Node.js 18+ and npm
- Python 3.11+
- Postgres
- Docker & Docker Compose (optional)

### Backend

```bash
cd backend
cp ../.env.example ../.env   # then edit it
pip install -r requirements.txt
alembic upgrade head   # create the tables
# first administrator (set ADMIN_EMAIL / ADMIN_PASSWORD in .env first)
python -m app.seed
uvicorn app.main:app --reload
```

### First login

The design has a login but no endpoint that creates a user, so a seed command creates the first administrator (role `administrator`) from `ADMIN_EMAIL` and `ADMIN_PASSWORD`. Run it once after the migrations, then sign in with those credentials.

### Frontend

```bash
cd frontend
npm install
npm run dev
npm run build
npm run test
```

### With Docker

```bash
docker compose up --build
```

### Environment variables

Copy `.env.example` to `.env` and set (secrets are left blank on purpose):

- `DATABASE_URL` - Full async SQLAlchemy DSN for the PostgreSQL database (asyncpg driver)
- `SECRET_KEY`
- `APP_ENV` - Runtime environment: development | production | test — FastAPI idiom for environment name
- `PORT` - TCP port the Uvicorn/FastAPI server listens on
- `HOST` - Bind address for the Uvicorn server
- `API_BASE_URL` - Canonical base URL of this API, used for self-referencing links and CORS validation
- `DEBUG` - Enable FastAPI debug mode and verbose error responses; must be false in production
- `WORKERS` - Number of Uvicorn worker processes; tune per CPU count in production
- `DATABASE_POOL_SIZE` - SQLAlchemy connection pool size; increase for production load
- `DATABASE_MAX_OVERFLOW` - Maximum connections allowed beyond DATABASE_POOL_SIZE before blocking
- `DATABASE_POOL_TIMEOUT` - Seconds to wait for a connection from the pool before raising an error
- `DATABASE_ECHO` - Log all SQL statements via SQLAlchemy; set true only in development
- `JWT_SECRET_KEY` - Secret key used to sign and verify JWT access tokens (HS256); minimum 32 bytes entropy
- `JWT_ALGORITHM` - Algorithm used for JWT signing: HS256 | RS256
- `JWT_ACCESS_TOKEN_EXPIRE_MINUTES` - Lifetime of an issued access token in minutes
- `JWT_REFRESH_TOKEN_EXPIRE_DAYS` - Lifetime of a refresh token in days before the user must re-authenticate
- `JWT_REFRESH_SECRET_KEY` - Separate secret for signing refresh tokens to limit blast radius if one key leaks
- `BCRYPT_ROUNDS` - bcrypt cost factor (salt rounds) for password hashing; 12 is the recommended production minimum
- `CORS_ALLOWED_ORIGINS` - Comma-separated list of allowed client origins for CORS; the React SPA origin(s)
- `CORS_ALLOW_CREDENTIALS` - Allow cookies/auth headers in cross-origin requests; must align with frontend fetch mode
- `TELEMATICS_MODE` - Selects the OdometerProvider implementation: mock (built-in test data) | live (real feed); no code change required to switch
- `TELEMATICS_LIVE_BASE_URL` - Base URL of the live telematics feed endpoint; required only when TELEMATICS_MODE=live
- `TELEMATICS_API_KEY` - API key for the live telematics provider; required only when TELEMATICS_MODE=live
- `TELEMATICS_POLL_INTERVAL_SECONDS` - How often (seconds) the background task polls the telematics feed for new odometer readings
- `TELEMATICS_REQUEST_TIMEOUT_SECONDS` - HTTP client timeout when calling the live telematics endpoint
- `RATE_LIMIT_WINDOW_SECONDS` - Rolling time window in seconds over which request counts are measured
- `RATE_LIMIT_MAX_REQUESTS` - Maximum number of requests a single client IP may make within RATE_LIMIT_WINDOW_SECONDS
- `REDIS_URL` - Redis DSN used for API response caching (depot due-list) to meet the p95 2 s SLA under load
- `CACHE_DEFAULT_TTL_SECONDS` - Default TTL for cached responses; tune per endpoint sensitivity vs. freshness requirement
- `CACHE_DUE_LIST_TTL_SECONDS` - TTL specifically for the depot due-list cache entry; kept short to reflect timely overdue status
- `LOG_LEVEL` - Python logging level: DEBUG | INFO | WARNING | ERROR | CRITICAL
- `LOG_FORMAT` - Log output format: json (structured, for log aggregators) | text (human-readable for local dev)
- `ADMIN_EMAIL` - email of the first administrator
- `ADMIN_PASSWORD` - password of the first administrator (set it before seeding)

## Open questions in the design

The design package left these undecided; the generated code makes a default choice that the design team should confirm:

- **There is a login but no way to create the first user**
- **No endpoint lists `users`, but screens choose one**
- **Role `internal` is not one of the stored roles**
